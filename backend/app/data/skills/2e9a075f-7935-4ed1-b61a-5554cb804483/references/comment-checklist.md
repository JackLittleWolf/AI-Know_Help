# コメント・Javadoc チェックリスト

コードレビューや自己確認用。コメントに関する指摘事項をチェックリスト形式でまとめたもの。

---

## クラス

- [ ] **クラスコメントは「目的＋概要」があるか**  
  - NG: 「AI関連API」だけの一行  
  - OK: 何のクラスか＋何をするか（必要なら `<p>` で概要を追記）

- [ ] **全プロジェクトで共通のことは書かない**  
  - NG: 「多言語対応のエラーメッセージを行う」など、どこでもやる処理の説明  
  - OK: そのクラス固有の責務・振る舞いだけ書く

---

## フィールド（クラス変数）

- [ ] **クラスのフィールドにコメントがあるか**  
  - 例: `private final QWenService qwenService;` → 「QWen API を呼び出して Todo 候補を生成するサービス」など  
  - 意味が自明でないもの、依存の役割が分かるようにする

- [ ] **Entity の各フィールドに説明があるか**  
  - テーブルカラム対応・型・取り得る値（例: priority: high/medium/low）を 1 行で

---

## メソッド（Javadoc）

- [ ] **public メソッドに Javadoc があるか**  
  - 概要 1 文＋必要に応じて `@param` `@return` `@throws`

- [ ] **private メソッドにも概要があるか**  
  - 役割が分かる程度の 1 行でよい

- [ ] **引数・戻り値・例外が明記されているか**  
  - 複数引数なら `@param`、戻り値があるなら `@return`、例外を投げるなら `@throws`

---

## React / フロントエンド

- [ ] **コンポーネント先頭に目的を 1 行**  
  - 何を表示・担当するコンポーネントか。自明な名前なら省略可

- [ ] **公開関数（API・ユーティリティ）の JSDoc に `@param` / `@returns` があるか**  
  - 引数があるなら `@param`、戻り値があるなら `@returns` を書く。概要 1 文とセットで

- [ ] **props の意味が分かるか**  
  - 型だけでは分からないもの（例: 単位・取り得る値）はコメントまたは JSDoc

- [ ] **複雑なロジック・副作用に理由または要約**  
  - useEffect / カスタムフック内で「なぜこうしているか」が分かる程度。自明なら不要

---

## その他

- [ ] **日本語で統一しているか**（プロジェクト方針に従う）

- [ ] **冗長な説明を避けているか**  
  - コードから明らかなこと、他と重複する説明は省く
